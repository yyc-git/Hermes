# 教材目录修订 Skill（编辑反馈驱动）

> 触发词：兄弟说「看下这个文档的批注」「按批注/编辑反馈改目录」「编辑发了批注版」「目录修订」「砍掉 X 章 / 在目录加 XX」
> 项目：`D:\Github\VibeCodingBook\`（contents/目录.md 是基线，编辑已确认）
> 输入：① 编辑批注版 .docx ② 微信聊天记录 md ③（可选）两份资料整理/新想法

## 背景与原理

- 出版社编辑的反馈通常以两种形态到达：**批注版 .docx**（标题表述、结构建议）+ **微信聊天记录**（方向性决策，如删哪章、写样章优先级）
- 编辑通常明示「整体结构不要动，目录已和责编确认」——**修订纪律 = 小改标题/删指定章，不大改结构；任何结构调整必须给出详细理由**
- 目录 md 是基线资产：修订**必须生成新文件**（命名带日期），原文件保留供对照和溯源

## 流程

### Step 1: 读批注（docx comments）
- 🔴 普通 read_file 读不到 Word 批注——批注在 docx 包 `word/comments.xml`，正文锚点在 `word/document.xml`
- 直接用 `docx-comments-extract` skill（脚本 `scripts/extract-docx-comments.ps1`），输出「批注正文 + 锚定段落」，用批注 id 关联
- 产出「位置 → 批注内容」对照表，提炼批注主线（常见 4 类：命名规范化 / 方向性质疑 / 篇幅删减 / 冗余删除）

### Step 2: 读微信聊天记录（决策来源）
- 决策摘要通常在 `笔记/素材整理/微信聊天记录-与编辑<名>-<日期>.md` 尾部
- 区分「编辑明确建议」（照做）vs「编辑疑问待拍板」（列给兄弟选，如 Brief vs Agent Brief）

### Step 3: 归档批注清单（推荐）
- 存 `笔记/素材整理/<原文件名>_批注清单.md`：批注人/时间、逐条对照表（位置→内容→类型）、主线归纳、待拍板 checklist
- 原始批注版 docx 保留不删

### Step 4: 修订目录（核心纪律）
- 🔴🔴 **生成新 md 文件，命名带日期**（如 `contents/目录_2026_08_18_修订版.md`），**绝不覆盖** `contents/目录.md`
- 标题表述类批注（去「了解/理解/对比」动词头、从0→从零、统一术语 Brief→Agent Brief）可批量落地
- 方向性/删减类决策**必须等兄弟拍板**（如砍第9/16章是兄弟定的，编辑只建议）
- 删章后编号顺延重排（原第10-15章→新第9-14章），学时表联动调整（删 n 章减 n×该章学时，总数同步如 64→60）
- 保持教材规范：7 级编号、目录到 3 级、标题无标点、每章本章小结+课后练习、学时全偶数

### Step 5: 自查
- 章节数：`Select-String "^### 第"` 行数 = 预期
- 编号连贯无跳跃：`Select-String "^(\d+)\.(\d+)"` 提取去重
- 学时求和 = 头部声明总数
- 被删章节无残留

## 重要注意事项

### 🔴 结构约束优先
编辑确认过的目录结构是强约束。兄弟说「砍 9、16 章」→ 只砍这两章，其余顺延；兄弟说「结构最好不大改」→ 新增内容先问放哪、给理由。未经拍板不擅自增删章节。

### 🔴 学时联动
删章/加章必须同步学时分配总表 + 头部「全书建议 X 学时」说明（如 64→60，理论/案例/机动三部分同步）。

### 🔴 工具升级类内容（2026-08-18 实战）
兄弟的新想法（如案例章改用 Multica/OpenClaw/Hermes、新增「套餐/免费模型省 token」）→ 落到底稿合适小节，标题可微调或新增小节，但章节总数和学时表结构保持。调度 OpenCode Pro 改目录时：工作目录是 `D:\Github\VibeCodingBook`（非 GTS-Play），brief 里写清输入材料、新想法、硬约束（14章不变、输出新文件、不做清单、三态定义），brief 文件用 `.opencode-brief-<任务>.md` 放 VibeCodingBook 根目录。

### 🔴 交付物纪律（2026-08-18 兄弟拍板，两次纠正）
- **目录标题不带工具标注**：OpenCode 融合修订时会给案例章标题加括号工具标注（如「第9章 从零开发抓取文章和发布文章案例（OpenClaw）」）——兄弟明确要求**去掉**。工具/平台分配（OpenClaw 为主、Multica/Hermes 各一案例）只写进修订说明笔记，正文写作时再体现，**不进目录标题**。
- **修订说明抽出到笔记**：OpenCode 会在目录文件末尾写「本次修订说明/未采纳建议/工具分配表」整段——兄弟要求**从目录文件移除，提取存 `笔记/写书记录/YYYY-MM-DD-<主题>说明.md`**。目录文件保持纯目录（头部+14章+附录），不含说明性段落。
- 处理手法：工具标注用 patch 逐处替换（学时表 + 正文章标题）；末尾大段说明用 PowerShell `Get-Content` 定位行号 + `Set-Content` 截断（patch 的 old_string 含中文引号「」时易匹配失败）。
- 复核：`Select-String "OpenClaw|Multica|Hermes"` = 0、`Select-String "本次修订说明|工具分配说明"` = 0、章节数仍 = 14、每章小结+练习齐全、新增小节（如 6.3.4）保留。

### 关联
- `docx-comments-extract`（productivity）：读 docx 批注的通用技术 skill，本 skill 的 Step 1 依赖它
- `book-material`（gts）：写书资料搜集，本 skill 是其「反馈修订」阶段的下游
- 参考文件 `references/批注清单模板-2026-08-18实战.md`：批注清单模板 + 批注 4 类主线识别特征 + 实战关键点（锚点 id 关联、微信决策摘要位置、最终修订决策）

## 故障排查

| 现象 | 原因 | 处理 |
|------|------|------|
| 批注读不出 | read_file 只提取正文 | 用 docx-comments-extract skill 解包 |
| 编号跳号 | 删章后忘顺延 | Step 5 用 Select-String 校验 `^\d+\.\d+` 去重 |
| 学时对不上 | 删章忘联动 | 同步学时分配总表 + 头部总学时说明 |
| 覆盖了原目录 | 忘了新文件名 | 🔴 永远先起带日期的新文件名再写 |
| patch old_string 匹配失败 | 中文引号字符不一致（「」vs "） | 改用 PowerShell `Get-Content` + 行号定位 + `Set-Content` 截断（删末尾整段时） |
