# gts-plan-review — 方案审核 Skill

> 兄弟说「审核方案」「方案审核」时触发。引用 opencode-schedule 调度协议。

## 触发词

- 「审核方案」「方案审核」「plan review」「审核这个方案」

## 流程概述

三阶段审核流程，每轮调度不同模型独立审核，后一轮叠加前一轮的报告进行审核，最终由最强模型裁决。

**每轮完成后必须向兄弟汇报结果，等兄弟确认后再进行下一轮。**

```
[收集资料] → [Kimi K3 报告2] → [汇报等确认] → [GLM-5.2 Max 报告3] → [汇报等确认] → [DeepSeek Pro Max 最终裁决] → [汇报]
```

---

## 前置条件

1. **确认审核范围**：兄弟说审核什么方案/报告，确认相关文件路径
2. **确认输出目录**：审核报告保存路径，默认 `笔记/项目文档/reviews/<日期>-<方案名>/`
3. **启动 OpenCode Web UI**（如果未启动）：Dispatch 前置检查

---

## 调度协议

引用 `skills/opencode-schedule/SKILL.md` 的全部调度规则，包括：
- 写 `.opencode-brief.md` → `$brief` 变量传参
- Pre-dispatch 完整性检查清单（brief 文件存在、非空、Web UI 可访问）
- Dispatch 命令模板（`--attach`、`--no-replay`、`--dir` 绝对路径）
- poll 步骤（数据量纪律：<10行、每行<50字、总<200 tokens）
- 需要停 OpenCode → 收集信息判断 → 确认需要停 → 调度 gts-opencode-stop
- 主 session 不重复跑验证

---

## 详细步骤

### Step 0: 准备

1. 读兄弟指定的方案/报告文件，确认文件路径列表
2. 创建输出目录：`D:\Github\GTS-Play\笔记\项目文档\reviews\<日期>-<方案名>\`
3. 如果兄弟未指定方案名 → 询问
4. 确认后开工

### Step 0.5: 选择第1轮模型

在进入第1轮前询问兄弟：

```
第1轮审核用哪个模型？
[1] Kimi K3（默认，回车即可）
[2] GPT-5.6 Sol Xhigh

> 
```

- 回车 / 1 → 设置 `context.firstRoundModel = "kimi-k3"`
- 2 → 设置 `context.firstRoundModel = "gpt-sol-xhigh"`

> 📊 **状态追踪：** 记录到 context

---

### Step 1: 第1轮审核

调度 OpenCode 审核所有原始报告/方案，出报告2。

模型按 Step 0.5 的选择决定：
- `kimi-k3` → `opencode-go/kimi-k3`，报告2文件名 `report2-kimi-k3.md`
- `gpt-sol-xhigh` → `opencode/gpt-5.6-sol-xhigh`，报告2文件名 `report2-sol-xhigh.md`

**brief 内容：**
```markdown
## 任务：方案审核（第1轮）

### 审核范围
审核以下文件，进行方案审核：
<列出所有方案/报告文件路径>

### 审核标准
1. 方案完整性 — 是否覆盖所有关键点？
2. 技术可行性 — 方案中的技术方案是否可行？
3. 风险评估 — 是否有未识别的风险或隐患？
4. 一致性 — 方案各部分之间是否自洽？
5. 可实施性 — 方案是否具有可操作性？

### 输出要求
- 输出格式：Markdown
- 输出文件：`<项目根目录>/笔记/项目文档/reviews/<日期>-<方案名>/report2-{模型名}.md`
- 内容结构：
  - 审核摘要（3-5句）
  - 各维度评分（1-5分）+ 说明
  - 发现的问题/风险列表
  - 改进建议
  - 补充建议

### 约束
- 不能修改任何源文件
- 不能写代码
- 不能修改 doc/ 和 笔记/语雀知识库/ 目录
- 这是方案审核，不是代码审核

### 共享规约
共享规约见 docs/agent-context.md
```

**调度方式：** 按 `skills/opencode-schedule/SKILL.md` 标准流程执行。
- Kimi K3 → 模型 `opencode-go/kimi-k3`，报告文件名 `report2-kimi-k3.md`
- GPT-5.6 Sol Xhigh → 模型 `opencode/gpt-5.6-sol-xhigh`，报告文件名 `report2-sol-xhigh.md`

**poll 等待完成** → 确认报告2已生成。

### Step 1.5: 汇报第1轮结果，等确认

1. 读报告2摘要（前 3-5 行 + 各维度评分 + 主要问题列表）
2. 向兄弟汇报：
   - ✅ 第1轮审核完成（选定的模型：Kimi K3 / GPT-5.6 Sol Xhigh）
   - 各维度评分概览
   - 主要发现的问题/风险（摘要）
   - 报告2路径
3. **桌面通知**：`msg * "兄弟，方案审核第1轮完成了，看看结果？"`
4. **等兄弟说「继续」再走 Step 2**

### Step 2: 第2轮 — GLM-5.2 Max 审核

兄弟确认后，调度 OpenCode GLM-5.2 Max 审核原始报告 + 报告2，出报告3。

**brief 内容（在 Step 1 基础上增加）：**
```markdown
## 任务：方案审核（第2轮）

### 审核范围
审核以下文件，进行方案审核：
<列出所有方案/报告文件路径>

### 已有审核报告
同时审阅第1轮审核报告：`<report2路径>`
需要判断：
- 第1轮审核是否完整？是否有遗漏？
- 是否认同第1轮提出的问题？
- 是否有不同于第1轮的视角？

### 审核标准
（同上 — 方案完整性、技术可行性、风险评估、一致性、可实施性）

### 输出要求
- 输出文件：`<项目根目录>/笔记/项目文档/reviews/<日期>-<方案名>/report3-glm.md`
- 内容结构：
  - 审核摘要
  - 各维度评分 + 说明
  - 对第1轮审核的回应（同意/不同意/补充）
  - 新增发现的问题/风险
  - 新增改进建议
  - 与第1轮的分歧点

### 约束
（同上）
```

**调度方式：** 按 `skills/opencode-schedule/SKILL.md` 标准流程执行，模型 `opencode-go/glm-5.2 --variant max`。

**poll 等待完成** → 确认报告3已生成。

### Step 2.5: 汇报第2轮结果，等确认

1. 读报告3摘要（前 3-5 行 + 对第1轮的回应 + 新增发现）
2. 向兄弟汇报：
   - ✅ 第2轮审核完成（GLM-5.2 Max）
   - 对第1轮的认同/分歧
   - 新增发现的问题
   - 报告3路径
3. **桌面通知**：`msg * "兄弟，方案审核第2轮（GLM-5.2 Max）完成了，看看结果？"`
4. **等兄弟说「继续」再走 Step 3**

### Step 3: 第3轮 — DeepSeek Pro Max 最终裁决

兄弟确认后，调度 OpenCode Pro Max 审核原始报告 + 报告2 + 报告3，出最终报告。

**brief 内容（在 Step 2 基础上增加）：**
```markdown
## 任务：方案审核（最终裁决）

### 审核范围
审核以下文件，进行方案最终裁决：
<列出所有方案/报告文件路径>

### 已有审核报告
同时审阅前两轮审核报告：
1. 第1轮（选定的模型 — Kimi K3 / GPT-5.6 Sol Xhigh）：`<report2路径>`
2. 第2轮（GLM-5.2 Max）：`<report3路径>`
3. 原始方案/报告：<路径>

你的角色是最终裁决者。判断：
- 两轮审核中有哪些一致赞同的结论？
- 两轮审核中有哪些分歧？站在哪个立场更合理？
- 哪些建议是高质量的应该采纳？哪些可以忽略？
- 是否有两轮都遗漏的关键问题？

### 审核标准
（同上 — 方案完整性、技术可行性、风险评估、一致性、可实施性）
增加最终裁决的标准：
- 优先级排序 — 哪些问题必须解决？哪些可以放一放？
- 综合判断 — 方案整体是否可行？需要多大程度的修改？

### 输出要求
- 输出文件：`<项目根目录>/笔记/项目文档/reviews/<日期>-<方案名>/final-report.md`
- 内容结构：
  - 最终裁决摘要（核心结论）
  - 各方共识点
  - 各方分歧及裁决
  - 最终评分（各维度 1-5 分）
  - 必须解决的问题清单（优先级：P0/P1/P2）
  - 改进建议（采纳/拒绝及理由）
  - 总体结论：通过 / 有条件通过 / 不通过
  - 下一步行动建议

### 约束
（同上）
```

**调度方式：** 按 `skills/opencode-schedule/SKILL.md` 标准流程执行，模型 `opencode-go/deepseek-v4-pro --variant max`。（⚠️ Pro max 本机 exec 环境有 LLM 静默失败风险——2026-08-10 定稿；若发生：按 opencode-schedule 续跑 `-m` 原模型规则唤醒，仍不活再 stop）

**poll 等待完成** → 确认最终报告已生成。

### Step 4: 汇报最终结果

1. 读最终报告摘要（前 3-5 行 + 结论部分）
2. 向兄弟汇报：
   - ✅ 三轮方案审核全部完成
   - 参与模型：Kimi K3 / GLM-5.2 Max / DeepSeek Pro Max
   - 最终裁决结论：通过 / 有条件通过 / 不通过
   - P0 关键问题摘要
   - 最终报告路径
3. **桌面通知**：`msg * "兄弟，方案审核全部完成，最终报告在 reviews/<日期>-<方案名>/"`

---

## 🔴 硬性规则

1. **每轮完成后必须汇报，等兄弟确认才进下一轮**
2. **禁止修改任何源文件** — 方案审核只产出报告，不动代码
3. **禁止修改 doc/ 和 笔记/语雀知识库/ 目录**
4. **不在兄弟确认前裁断** — 最终报告是给兄弟参考的，审核结果不能自动决策
5. **每轮是独立审核** — 后一轮不能完全复制前一轮的结论，要有独立判断
6. **三阶段必须完整执行** — 不能跳步或合并步骤
7. **模型选择按兄弟指定执行** — 如果兄弟指定不同模型，按兄弟说的
8. **引用 opencode-schedule SKILL.md 的完整调度协议** — dispatch 命令模板、poll 步骤、数据量纪律等全部适用
