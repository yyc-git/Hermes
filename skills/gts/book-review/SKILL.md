# 教材审核 Skill

> 触发词：兄弟说「审核书」「审核目录」「审核选题表」「按写书通用规则审核」「检查教材内容」等
> 目标项目：`D:\Github\VibeCodingBook\`（教材《Vibe Coding开发与应用》，人邮社出版）
> 关联技能：`textbook-publishing-workflow`（出版对接工作流）；`docx-comments-extract`（读编辑批注）；`docx-template-fill`（md→docx 模板填充）
> 已实测：2026-08-18 审核目录+选题表，28 条结论（25✅/2⚠️/1❌），无 🔴 退稿级问题

## 背景与原理

- 教材交付物（目录/选题表/正文）发给编辑前必须过审核，退稿级问题（政治红线）一票否决
- 审核依据：`笔记/章节笔记/教材编写红线清单.md`（人邮社规范）+ 项目笔记（批注清单/微信记录/修订说明）
- 审核规则固化后逐条执行，避免「凭感觉看一遍」漏掉关键规范
- 🔴 审核=只读不改，产出报告；修复是审核后的独立步骤（等兄弟拍板哪些改哪些不改）

## 审核规则（23 条，来自 2026-08-18 实测）

### A. 政治红线与内容安全（退稿级，一票否决）
- **A1** 无劣迹人物/争议企业/敏感人物（吴亦凡、马云、滴滴、Facebook、达赖等）
- **A2** 无外国宗教节日/外国标志元素/深肤色非黑发形象（游戏截图尤其注意）
- **A3** 港澳台表述规范：台湾配大陆、不单列、不与国家并列
- **A4** 无政治敏感：地图/国旗国徽/文革/领导人照片
- **A5** 无广告禁用语（秒杀/最佳/最低价）、无真实品牌广告
- **A6** 无网络用语、无负面评价社会事件

### B. 目录规范（教材结构）
- **B1** 章节数正确，无被删章节残留
- **B2** 学时总数正确，每章学时偶数
- **B3** 每章含「本章小结」+「课后练习」
- **B4** 7 级标题编号体系；目录到第 3 级标题
- **B5** 各级标题末尾无标点
- **B6** 标题无动词头（了解/理解/认识/掌握/对比）、「从0」→「从零」、Brief/Agent Brief 全目录统一
- **B7** 标题无工具标注（OpenClaw/Hermes/Multica）
- **B8** 更新点与正文一致（更新点声称的改动，正文确实改了）
- **B9** 页数估算 180~320、各章体量均等（约 30 页/章 ±）

### C. 选题表/表单规范
- **C1** 大板块齐全（选题思路/读者对象/作者情况/内容提要/配套教辅/市场分析/卖点分析/推广建议）
- **C2** 【】栏目完整不删
- **C3** 资源口径统一（本书：只承诺 PPT+教学大纲+习题答案+代码仓库/在线运行+简要线上演示，不承诺教案/微课/慕课/实验手册/MOOC/AR）——多处必须一致
- **C4** 内容提要 ≥200 字、不写教材目录
- **C5** 无模板残留（XXX博士/以下文字为示例/202x年/简要阐述/参考本书严格 等）
- **C6** 作者信息字段齐全，【待填】标注合理
- **C7** 关键数值字段已填（篇幅/交样章/交全稿时间）
- **C8** 无错别字/语病/用词统一（其它→其他、做/作、的地得、标点、数字）

### D. 交叉一致性与笔记一致性（🔴 重点）
- **D1** docx 与 md 内容一致（Word 无遗漏/错位/编码）
- **D2** 表单 docx 与源稿 md 内容一致（作者信息等字段）
- **D3** 目录新增内容在选题表/更新点中对应体现
- **D4** 工具分配与笔记记录一致
- **D5** 🔴 交付物与笔记一致性：12 条批注处理、删章决策、资源口径、目标销量/时间字段依据、作者情况/市场分析与笔记事实矛盾检查

## 流程

### Step 1: 确认审核对象 + 依据
- 对象：目录 md/docx、选题表 md/docx、正文章节等
- 依据：红线清单 + 修订说明 + 批注清单 + 微信记录 + 写作方法论 + 索引

### Step 2: 写 brief（调度 OpenCode Pro）
- 🔴 文档审核用 Pro：`volcark/deepseek-v4-pro-ga-260813`（火山 Pro 正式版优先，备选 opencode-go/deepseek-v4-pro）
- brief 必须写：全程中文、只读不改、23 条规则全文、三态定义（输出=报告路径+格式、失败态）、不做清单
- 报告写入 `笔记/写书记录/<日期>-<对象>审核报告.md`
- 报告格式固定：结论总览（通过率+严重度分布）→ A/B/C/D 逐条 ✅/❌+证据 → 问题清单（编号/位置/问题/建议/严重度🔴🟡🟢）→ 范围与方法说明
- 调度细节照 opencode-schedule skill（--attach 4098、--title、--no-replay、--auto、--dir）

### Step 3: 监控（wait 脚本）
- dispatch 后立即拿 sessionId → `node scripts/wait-opencode-session.mjs <id> <maxWait> 300 --exit-on-stuck --title "<title>"`
- 完成三重判定：wait reason=stop + DB step-finish + 读报告文件确认生成

### Step 4: 读报告 → 汇报兄弟
- 汇总：通过率、问题数、严重度分布、重点确认项（笔记一致性/政治红线/目录规范）
- 列出问题清单，**等兄弟拍板哪些修哪些不修**（🔴 不擅自修，尤其涉及作者信息/编辑填写项）

### Step 5: 按兄弟指示修复（可选）
- 明确指示「修」的才动手；「不要作」的跳过
- md 用 patch 改；docx 用 python-docx 定点改 run（🔴 不重新生成，保留兄弟手填的字段）
- 修复后独立验证：读回 docx 确认修复生效 + 板块完整 + 无残留

## 重要注意事项

### 🔴 审核只读不改
OpenCode brief 里必须写死「不改任何被审文件」。修复是独立步骤，等兄弟拍板。兄弟说「不要作」的项（如学校年用量/复选框）坚决跳过。

### 🔴 docx 修复必须定点，不重新生成
docx 里可能有兄弟在 WPS 手填的值（如年龄 37）。重新生成会丢。用 python-docx 打开定位到具体 run 替换，或整段重建（跨 run 时）。修完读回验证。

### 🔴 审核规则可扩展
不同交付物增删规则：正文章节要加「图/表/代码/参考文献规范」（红线清单第四~六节）；选题表 C 类聚焦表单字段。

### docx 读取用 python-docx
- 环境：`D:\4.1\python\bin\python.exe`（已装 python-docx 1.2.0）
- 读取正文+表格：`Document(path).tables[0]`，合并单元格按 `_tc` 去重
- 中文/正则写临时 .py 文件，不写内联 `-c`

### 验证脚本命名
临时验证脚本用 `hermes-verify-*` 前缀放 Temp，用完删除。

## 故障排查

| 现象 | 原因 | 处理 |
|------|------|------|
| 审核报告缺某条规则结论 | brief 规则没写全 | brief 逐条贴 23 条规则，不得浓缩 |
| docx 修复后丢手填值 | 重新生成覆盖了 | 定点改 run，不重新生成 |
| 审核把「第6章新增…」误计为章节 | 正则 `^第\d+章` 误匹配列表项 | 校验排除「新增」字样 |
| 报告行数不对/漏板块 | 审核对象读取不全 | brief 明确列出全部文件路径 |
| Pro 审核跑很久 | 读 10+ 文件 + 逐条比对 | maxWait 3000s+，Pro 静默正常 |
