# 教材出版对接工作流 Skill

> 触发词：兄弟说「修改目录」「填选题表」「选题申报」「选题审查」「处理编辑批注」「看批注」「写样章」「发给编辑」等
> 目标项目：`D:\Github\VibeCodingBook\`（兄弟的教材《Vibe Coding开发与应用》，人邮社出版）
> 关联技能：`docx-comments-extract`（读取编辑批注版 docx 批注）；`book-material`（搜集外部资料/对本书启示，OpenClaw 迁移技能，后台 curator 不可 patch，需会话中手动 patch）；`book-review`（审核书交付物：目录/选题表，23 条教材规则 + 调度 OpenCode Pro）；`docx-template-fill`（md→docx 模板填充：选题表/申报表）

---

## 背景与原理

- 教材出版有固定节奏：**目录定稿 → 编辑批注 → 目录修订 → 写样章 → 填选题申报表 → 报选题 → 写全稿**
- 编辑（人邮社佘战文/「丹」）通过「批注版 .docx」反馈目录意见，通过微信沟通删章/结构调整等方向性决策
- 修订是迭代的：每轮另存新文件，保留历史版本，绝不覆盖原始目录

## 目录修订纪律（兄弟 2026-08-18 拍板，硬性）

1. 🔴 **另存带详细日期的新 md 文件**（如 `目录_2026_08_18_修订版.md`），**绝不覆盖**原 `目录.md` 与任何历史版本
2. 🔴 **「修订说明」不留在目录文件里**——改动内容/理由抽出来存 `笔记/写书记录/<日期>-<说明>.md`，目录文件保持纯净只放目录
3. 🔴 **目录标题不给工具/平台标注**（如 OpenClaw/Hermes/Multica）——工具分配等细节写进笔记，正文写作时再体现
4. 砍章节后必须重排后续章节编号，并验证：章节数、学时总数（删 1 章 2 学时→总学时-2）、每章「本章小结+课后练习」齐全、无被删章节残留
5. 综合多方输入修订（编辑批注 + 微信记录 + 资料启示 + 作者新想法）时，可调度 OpenCode（文档写作任务用 Pro：`volcark/deepseek-v4-pro-ga-260813`），brief 写清「结构不要大改 + 任何结构调整必须给详细理由」
6. 🔴 **交付给编辑的目录附「与原始目录的更新点」对比表**（2026-08-18 兄弟要求「方便编辑查阅」）——放在目录文件末尾「附录」之后新增 `## 与原始目录的更新点` 一节，开头注明对比基准（原始目录版本 + 章数/学时），五个小节：①章节删减（表格：删了哪几章 + 理由）②章节编号顺延（原X~Y章→新A~B章 + 学时变化）③标题表述调整（表格：位置/原标题/新标题，按编辑批注逐条列）④新增内容（如新小节）⑤结构保持（说明整体为小改动）。md 和 docx 都要同步补充（docx 用 md→docx 生成脚本重新生成，更新点里的表格/标题/加粗列表都支持）

## 选题表（选题申报表）填写要点

> 模板来自编辑【选题审查意见表】.docx，8 大板块必须填全，【】栏目保留不删。

1. **选题思路**【选题背景】【选题内容特点】【配套教材说明】【目标销量】【其他说明】
2. **读者对象**（学历/收入/零售/培训班三渠道）
3. **作者情况**（姓名/年龄/职称/学历/院校 + 一段式简介；缺的信息标【待填】）
4. **内容提要**（≥200 字，不写目录）
5. **配套教辅和服务**
6. **市场分析**（分析 3 本左右同类畅销教材）
7. **卖点分析**【内容特点】【资源特点】【服务特点】
8. **推广及销售建议**【名师执笔主编】【具体推广建议】

### 🔴 资源承诺口径（兄弟 2026-08-18 拍板）
- **只承诺实际能提供的资源**：教学 PPT、教学大纲、习题答案、案例代码仓库/在线运行、简要线上演示或基础课程讲解
- **不承诺**：教案、微课/慕课、实验指导手册、MOOC、AR/VR 动画
- 全文口径必须统一（选题思路/内容提要/配套教辅节/卖点资源特点/其他说明 5 处一致），改一处必须同步其余各处
- 作者「100 余小时线上课程」「206 篇博文」「2 个 QQ 群」是**资历描述**可保留，≠ 承诺提供资源

### 市场分析写法
- 必须选 2~3 本「与自己所写教材相同的畅销教材」分析（内容/销售/优缺点/与本书差异）
- 兄弟的书写的是 Vibe Coding（2026 年高校教材空白）→ 分析三类相近书：①传统编程入门（无 AI）②AI 通识科普（不可实操）③AI 工具操作书（无教学结构）
- 书名拿不准就泛指（如「各版本《Python 程序设计》」），**不编造具体书名/销量**；要点名再补

### 🔴 篇幅/字数/交稿时间评估（兄弟 2026-08-18 纠正：用实测数据，别拍脑袋）
- **评估交稿篇幅/字数/时间时，先搜索记忆/笔记里的实际写作数据做锚点，不要用通用公式**（如「每学时4-5页」「AI初稿5-7万字/天」这类经验值会被兄弟纠正「你要参考之前写作的整个过程来评估」）
- 本项目实测锚点（来自 daily logs + 写作方法论）：
  - 《Vibe Coding 多人游戏系列》：35 篇 ≈ 15~20 万字，**约 3 天密集完成**（07-06 发 4 篇；07-07 一天续写 26 篇 P9-P34 + 重写 P8-P14(35→31) + 全部 23 篇薄文扩写，总增量 ~3,178 行）
  - 换算：AI 初稿产出约 **5~7 万字/天**；方法论全文在 `笔记/系列博文参考/写作过程-规范-经验.md`（大纲先行→逐篇→连载）
- 本书（14 章/60 学时/约 30 万字）评估：量是系列的 1.6~2 倍；但**逐章确认 + 4 轮修改 + 教材规范是瓶颈**（系列是批量发布模式，无此环节）
  - 建议值：篇幅 **300 页/约 30 万字**；交样章 **2026-09-30**（1 章约 3~4 周：AI 初稿 2-3 天 + 确认 + 4 轮修改）；交全稿 **2027-02-28**（兄弟 2026-08-18 最终拍板，比建议的 01-31 再多留时间，稳妥优先）
- 时间估算逻辑要写清（每章耗时 × 章数 + 缓冲），交兄弟拍板，不擅自定死

### 选题表 → 填好的 docx（2026-08-18 实测流程）
- 兄弟确认填写稿 md 后，要求「写进编辑模板 docx，作为新文件」——这是报选题前必须交付的成品
- 做法：把填写稿 md 内容填进模板 `【选题审查意见表】_<日期>_<编辑名>.docx`，另存新文件，**不覆盖模板原件**
- 实现走 **`docx-template-fill` skill**（productivity 分类，2026-08-18 创建）+ `scripts/fill_docx_template.py`（python 用 `D:\4.1\python\bin\python.exe`，已装 python-docx）
- 模板是单表格式：R8-R15 行 = 8 大板块内容区；R0 书名、R3 作者、R5/R6 交样章/交全稿时间单独填
- 🔴 兄弟没定的字段（年龄/职称/交样章时间/学校年用量/篇幅）填 `【待填】`，**别编造日期/数值**
- 生成后读回验证：8 板块非空 + 模板指导行/示例占位零残留 + 关键栏目关键词齐全
- 🔴 **WPS 锁文件坑（2026-08-18 实锤）**：兄弟 WPS 开着 docx 时，`doc.save(原路径)` 报 PermissionError、`Move-Item` 报「文件存在」。先 `doc.save(临时路径)`，再尝试替换；锁定时把更新版放到目标位置（如 contents/），明确告知兄弟「关闭 WPS 后我再删旧版」，改完独立验证目标那份

## 编辑沟通要点（2026-08-18 微信记录）

- 编辑对目录态度：「整体结构不要大动，已和责编确认好了」→ 修订以标题表述微调为主，删章/加节前先想清楚
- 编辑建议写样章：**第 8 章 或 第 9 章**（原第 10 章抓取发布）
- 流程：目录调整 → 写样章 → 填选题申报表 → 报选题

## 验证清单（修订/填写完成后自查）

- [ ] 新文件已另存，原文件未被覆盖
- [ ] 修订说明已抽到 `笔记/写书记录/`，目录文件无残留说明段
- [ ] 章节数正确（删 2 章后 14 章）、学时总数正确（64→60）
- [ ] 每章有「本章小结 + 课后练习」
- [ ] 标题无动词头（了解/理解/认识/掌握/对比）、「从0」→「从零」、Brief/Agent Brief 全目录统一
- [ ] 选题表全文资源口径统一（无教案/微课/慕课/实验手册残留）
- [ ] 7 级标题编号、目录到 3 级、标题末尾无标点

## 目录/选题表 审核（调度 OpenCode Pro，2026-08-18 实测）

> 触发：兄弟说「审核目录/选题表」「按写书通用规则审一遍」「加入查笔记的一致性」等。文档审核任务用 OpenCode Pro（`volcark/deepseek-v4-pro-ga-260813`），brief 写清「**只读不改文件** + 输出审核报告到 `笔记/写书记录/<日期>-目录选题表审核报告.md`」。

**审核规则框架（23 条基础，Pro 执行时按子项细分到 ~28 条）——可直接复用进 brief：**

- **A. 政治红线 6 条**（退稿级一票否决）：A1 劣迹人物/争议企业/敏感人物；A2 外国宗教节日/标志元素/深肤色非黑发形象；A3 港澳台表述规范；A4 地图/国旗/文革/领导人照片；A5 广告禁用语（秒杀/最佳/最低价）/真实品牌广告；A6 网络用语/负面评价社会事件
- **B. 目录规范 9 条**：B1 章节数（14 章无被删残留）；B2 学时总数（60）+ 每章偶数；B3 每章小结+课后练习；B4 7 级标题/目录到 3 级；B5 标题末尾无标点；B6 无动词头/「从零」/Agent Brief 统一；B7 标题无工具标注；B8 更新点与正文一致（交叉核对）；B9 页数 180~320/各章体量均等
- **C. 选题表规范 8 条**：C1 8 大板块齐全；C2 【】栏目完整不删；C3 资源口径 5 处统一（无教案/微课/慕课/实验手册/MOOC/AR）；C4 内容提要 ≥200 字不写目录；C5 无模板残留（XXX博士/以下文字为示例/202x年/简要阐述为什么/参考本书严格/哈工大）；C6 作者信息字段+【待填】合理；C7 三时间字段已填（篇幅300页/交样章2026-09-30/交全稿2027-02-28）；C8 错别字/语病/用词统一（其它→其他/做作/的地得/标点/数字）
- **D. 交叉与笔记一致性 5 条**：D1 目录 md↔docx；D2 选题表 md↔docx（⚠️ 实测坑：md 作者信息还是【待填】但 docx 已被兄弟 WPS 填实际值，两文件不一致）；D3 目录新增内容↔选题表/更新点对应；D4 工具分配↔笔记记录（OpenClaw×4/Multica×1/Hermes×1）；D5 🔴 交付物↔笔记一致性（12 条批注处理/删章决策/资源口径/目标销量时间依据/作者情况与市场分析与笔记事实无矛盾）

**审核产出**：报告含每类 ✅/❌ + 证据 + 问题清单（编号/位置/问题/建议/严重度🔴🟡🟢）。实测 2026-08-18 审出 5 问题（D2-1 作者信息 md/docx 不一致🟡、D2-2 学校年用量 XXX 占位🟡、D2-3 书稿情况复选框未勾🟡、C3-1 在线运行环境漏写🟢、C8-1「学中做做中学」缺顿号🟢），无退稿级。

**审核后处理纪律（兄弟 2026-08-18 拍板）**：把问题清单逐项报给兄弟，**兄弟逐项拍板哪些修、哪些「不要作」**——说「不要作」的就跳过（本次 D2-2 学校年用量、D2-3 复选框被兄弟明确跳过），不自己决定全修。让修的（本次 D2-1/C3-1/C8-1）直接修：D2-1 这类「md 与 docx 不一致」以 docx 实际值（兄弟 WPS 填的）为准同步 md，不要反着来。

## 目录 md → docx 生成（2026-08-18 实测复用）

- 参考 2026-08-12 目录 docx 规格：**正文宋体五号 1.5 倍行距、标题黑体**（文档标题16pt居中/一级14pt/章12pt/节11pt/小节10.5pt）、学时表带框线、页边距上下2.54 左右3.18cm
- python-docx（本机 `D:\4.1\python\bin\python.exe`）生成：HTML 注释块（`<!-- -->`）跳过、markdown 表格转带框线表、`N.N.N`/`N.N`/`A.x` 识别为标题层级
- 生成后必做 ad-hoc 验证（写临时脚本 `hermes-verify-` 前缀，用完即删）：python-docx 读回 + 章节数/学时/无被删残留/无工具标注/无修订说明残留断言（实测 29 项全过）
- 更新点对比表要同步进 docx（生成脚本需支持表格/标题/加粗列表）

## 提交纪律（gts-submit-save 双仓库，2026-08-18 实测）

- 兄弟说「提交」时，写书成果在 **VibeCodingBook**（`D:\Github\VibeCodingBook`），不是 GTS-Play。gts-submit-save 默认是 GTS-Play，所以**先列仓库选项问兄弟提交哪个**，确认后再走该 skill 流程（清理 .opencode-brief-*.md 临时文件 → git add contents/ 笔记/ docs/ → 交叉检查 → commit → push）。
- 🔴 GTS-Play 的 xiahui 线改动（.workflow 日志、mmd_tool 源码、AGENTS.md 等）**完全不碰**——不属于写书任务。
- 编辑批注附件（`笔记/素材整理/<日期>-编辑批注附件/*.docx`）是编辑原始文件，兄弟拍板「一并提交存档」。
- commit message 英文（PS 中文 GBK 乱码纪律），如 `doc: 目录资料融合修订版 + 选题表 + 审核报告 (2026-08-18)`。
- 记忆保存走 gts-save-memory（daily log 追加到 GTS-Play `笔记/memory/openclaw-archive/daily/<日期>.md`，不 push）。
