# 把内容填入 docx 模板 Skill

> 触发词:兄弟说「填选题表」「把 xxx 内容写入 docx 模板」「生成填好的 Word/申报表」「表单 docx」等
> 场景:教材出版选题表/申报表等「表格式 docx 模板」需要填入内容后另存新文件
> 已验证:2026-08-18《Vibe Coding开发与应用》选题表(人邮社【选题审查意见表】模板,23 行×15 列大表格,8 大板块全填 + 验证 20 项全过)

## 背景与原理

- 出版社的选题表/申报表通常是**一个巨大的表格**(如 23 行×15 列),8~10 个栏目各占一行,内容区是**合并单元格**(一行内多列合并成一个大 cell)
- 目标:把 md 源稿(按 `## 板块` 分节)的内容,逐板块填入模板对应行的内容区,**另存新文件,绝不覆盖模板原件**
- 工具:`python-docx`(本机 python: `D:\4.1\python\bin\python.exe`,已装 python-docx 1.2.0 + lxml)

## 环境

- python: `D:\4.1\python\bin\python.exe`(Python 3.11,已验证)
- python-docx: 已安装(2026-08-18)
- 若缺:`D:\4.1\python\bin\python.exe -m pip install python-docx`(后台跑,勿用 `&` 调用)

## 流程

### Step 1: 探查模板结构

写临时 .py 脚本(勿用 PowerShell 内联 `python -c`,中文/引号易乱码),列出:
1. 段落数、表格数
2. 每个表格的行数×列数
3. **每行去重后的独立单元格**(关键!合并单元格会让 `row.cells` 返回重复对象):
   ```python
   def indep(row):
       out = []
       for c in row.cells:
           if not any(c._tc is x for x in [o._tc for o in out]):
               out.append(c)
       return out
   ```
4. 确定每个栏目标题行号(如 选题思路=8、读者对象=9 …)

### Step 2: 准备内容源(md)

- md 按 `## 板块名` 分节,每节正文就是要填入的内容
- md 里可保留 markdown 标记(`**`加粗、`-`列表、`1.`编号),清洗时转纯文本

### Step 3: 清洗 md → 纯文本段落

规则:
- 去标题标记 `^#{1,6}\s*`
- 去加粗 `**(.+?)**`
- 去引用 `^>\s*`、去列表符 `^[-•]\s+`
- 空行保留为段落分隔;`---` 分隔线删除
- 去首尾空行

### Step 4: 🔴 剔除模板指导行(关键坑)

模板内容区开头常带灰色指导文字(给作者看的填写说明),**正式交付文档必须剔除**,否则编辑看到「（以下文字为示例，参考之后请删除）」等残留 = 交付事故。常见指导行前缀(按需扩展):

```python
TEMPLATE_HINTS = (
    "（简要阐述为什么提出此选题方案",
    "（目标读者定位、适合学历",
    "（内容提要，不少于",
    "（根据具体情况列写，资源配套须齐全",
    "（简要分析图书的重点销售区域及销售宣传建议",
    "（以下请选几本销售书",
    "（选几本销售书进行内容",
    "以下文字为示例",
    "参考：本书严格",
    "（以下文字为示例，参考之后请删除",
)
```

⚠️ 用**前缀匹配**而不是包含匹配,避免误删真实内容(如「（1）内容全面」这类正文)。

### Step 5: 填充并另存

- 对每个板块:定位到模板行 → `indep(row)[1]`(合并大 cell 起点)→ `set_cell_text` 清空旧内容写新段落
- `set_cell_text`:删 `cell.paragraphs[1:]`,清空首段 runs,首段写第一行,其余 `cell.add_paragraph()`
- 顶部单格字段(书名/作者名/日期)单独填
- 未定字段写 `【待填】`,**不要编造**(如预计交样章时间)
- `doc.save(新路径)` — 新文件名带日期,模板原件不动

### Step 6: 验证(必做)

写独立验证脚本(ad-hoc,非测试套件;文档任务无单测可跑):
1. 能否用 python-docx 打开(不损坏)
2. 各板块非空且字符数合理(内容提要应 ≥200 字)
3. **残留检查**:`XXX，博士` / `以下文字为示例` / `202x年` / `哈工大XXX` / `简要阐述为什么` / `不少于 200 字` 等全无
4. 关键关键词断言(如内容提要含「Vibe Coding」「14 章」)
5. 顶部字段(书名/作者)正确

## 重要注意事项

### 🔴 合并单元格去重
模板表格的 `row.cells` 对合并单元格返回**多个相同 `_tc` 的 Cell 对象**。直接 `cells[1].text` 可能取到标签列而非内容区。必须按 `_tc` 去重后取 `[1]`。

### 🔴 模板指导行/示例文字必须清干净
模板自带「（以下文字为示例，参考之后请删除）」「XXX，博士，教授，2006年…」等示例,这些是模板演示内容,正式交付必须全部剔除。用残留检查兜底。

### 🔴 不编造未知字段
年龄/职称/院校/交稿时间等兄弟没给的信息 → 标 `【待填】`,不要自己填编造的日期/数字。

### 🔴 不要用 `&` 调用 python
Hermes PowerShell 会把 `& $py` 误判为 backgrounding(报「Foreground command uses '&' backgrounding」)。直接用**完整路径**调用,不带 `&`。

### PowerShell 内联 python 中文乱码
涉及中文/正则/嵌套引号的 python 一律写临时 `.py` 文件再 `python.exe file.py`,不写内联 `-c`。

### 过程脚本用完即删
探查/填充/验证用的 `.tmp_*.py` 生成后用完删除,不留在仓库。

## 故障排查

| 现象 | 原因 | 处理 |
|------|------|------|
| `'CT_Tc' object has no attribute 'paragraphs'` | indep() 返回了 `_tc` 而非 Cell | indep 返回 Cell 对象(去重按 `c._tc is`),不要返回 `c._tc` |
| 填错位置(内容出现在标签列) | 合并单元格没去重,取错 index | 用 `indep(row)` 按 `_tc` 去重后再取 `[1]` |
| 内容区首段残留模板指导行 | 没过滤模板指导行 | 加 `TEMPLATE_HINTS` 前缀过滤 |
| 模板示例文字还在 | 只填了内容没清干净 | 残留检查兜底:搜 `XXX，博士`/`以下文字为示例`/`202x年` |
| `& $py` 报 backgrounding | Hermes PowerShell 误判 `&` | 改完整路径直接调用,不用 `&` |
