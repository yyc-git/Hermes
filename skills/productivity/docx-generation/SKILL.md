# Markdown → 排版 docx 生成 Skill

> 触发词:兄弟说「把目录生成为 docx」「把 xx 转 Word」「生成 docx」「目录 Word 版」等
> 场景:教材目录/正文章节从 md 生成排版好的 Word（黑体标题、宋体五号正文、1.5 倍行距、学时表带框线）
> 已验证:2026-08-18《Vibe Coding开发与应用》目录 md → docx（14 章 + 学时表 + 更新点表格，29 项验证全过）

## 背景与原理

- 教材交付给出版社需要 Word 版（编辑习惯 docx，非 md）
- 与 `docx-template-fill`（填现成表单模板，如选题表）是**两个不同场景**:
  - 模板填充 = 把内容填入编辑发来的表格模板（docx-template-fill）
  - 生成 = 从零把 md 排版成 docx（本 skill）
- 排版规格（人邮社教材）:正文宋体五号 1.5 倍行距、标题黑体（文档16/一级14/章12/节11/小节10.5pt）、页边距上下2.54cm左右3.18cm、**标题编号后空两格**（「1.1  标题」「第1章  标题」「A.1  标题」，数字与标题文字间 2 个空格，2026-08-18 编辑补充；目录规范全文见 `D:\Github\VibeCodingBook\笔记\写书记录\2026-08-12-目录改版.md` §7）

## 环境

- python: `D:\4.1\python\bin\python.exe`（Python 3.11，已装 python-docx 1.2.0）
- 脚本: `scripts/md_to_docx.py`

## 流程

### Step 1: 确认 md 源文件
- 教材目录 md（如 `contents/目录_xxx.md`），含 `#` 标题、`## 部分`、`### 第X章`、`1.1 节`、`1.1.1 小节`、`A.1 附录节`、markdown 表格、`>` 引用、`-` 列表

### Step 2: 生成
```powershell
D:\4.1\python\bin\python.exe md_to_docx.py --md "D:\...\目录_xxx.md" --out "D:\...\《书名》目录_xxx.docx"
```

脚本自动识别 md 结构并排版:
- `# ` 文档标题 → 16pt 黑体居中
- `## ` 一级标题 → 14pt 黑体
- `### 第X章 xxx` → 12pt 黑体（章级）
- `1.1 节` / `1.1.1 小节` / `A.1 附录节` → 按编号识别为 11/10.5pt 黑体
- `| 表格` → Table Grid 带框线，首行表头黑体加粗居中
- `> 引用` / `- 列表` / `**加粗**` / ```` 代码块 / `<!-- -->` 注释 → 正确处理

### Step 3: 验证（必做）

写独立验证脚本（ad-hoc，文档任务无单测）:
1. 用 python-docx 打开成功（不损坏）
2. 章节数正确（如 `^第\d+章` 匹配应为 14，注意**排除列表项误匹配**——如「第6章新增…」这类列表内容要过滤「新增」字样）
3. 无被删章节残留（如记账/第16章）
4. 关键小节标题存在（如 6.3.4、2.3 等）
5. 每章「本章小结 + 课后练习」齐全
6. 学时表存在且行数正确
7. 无工具标注残留（OpenClaw/Hermes/Multica，如标题不该带）
8. 无修订说明残留（如「本次修订说明」不应出现在目录 docx 正文）

### Step 4: 汇报
- 交付物路径 + 验证结果 + 提醒兄弟打开看排版

## 重要注意事项

### 🔴 验证「章节数」正则要排除列表项
`^第\d+章` 会误匹配「第6章新增 6.3.4…」这类列表/正文行。验证时加 `and '新增' not in text` 或只匹配 `^第\d+章\s`（带空格）。

### 🔴 验证「注释块/不出现内容」用行首锚定正则，别用 `in` 子串
判断某小节「不应出现」（如被 `<!-- -->` 注释掉的 3.3.1-3.3.4）时，**不能用 `'3.3.1' in full_text`**——`13.3.1 服务器部署` 这类其他编号会误命中，造成假 FAIL。2026-08-18 实坑：验证注释块时 `13.3.1/13.3.2` 里的 `3.3.1/3.3.2` 让脚本报 2 项失败，实际 docx 完全正确。正确写法：逐行 `re.match(r'^3\.3\.[1-4]\s', t)`。

### 标题层级
- `### 第X章` 和 `### 其他`（如 `### 一、章节删减`）都按二级标题（12pt）
- 若 md 里章节小节标题是裸文本（如「1.1 Vibe Coding」无 markdown 前缀），脚本用正则 `^(\d+\.\d+)\s+` 识别
- 🔴 **节/小节/附录标题由脚本重建文本**（`f"{编号}  {标题}"`，编号后固定双空格），不是原样保留 md 文本——所以 md 源改了编号后空格数后，**必须验证 docx 而不是只看 md**。2026-08-18 实坑：md 全改双空格后生成的 docx 节标题仍是单空格（脚本 162-170 行重建时用单空格），已改脚本为双空格。
- 🔴 **验证空格数用捕获组**：数编号后空格必须 `re.match(r'^(第\d+章|\d+\.\d+(?:\.\d+)?|A\.\d+)( +)', t)` 把全部空格收进 group(2)；写成 `^(编号) ( +)`（字面空格占位）会只数到 1，把正确双空格误报成单空格（2026-08-18 验证脚本自身踩坑）。

### 页边距
上下 2.54cm（1 英寸）、左右 3.18cm（1.25 英寸），人邮社教材默认

### 过程脚本用完即删
生成的临时验证 .py 用完删除，不留仓库

## 故障排查

| 现象 | 原因 | 处理 |
|------|------|------|
| 章节数验证多出 1 | 列表项「第6章新增…」被 `^第\d+章` 误匹配 | 验证排除「新增」或要求 `^第\d+章\s` |
| 表格乱/缺列 | md 表格行首尾 `|` 不一致 | 脚本 `strip("|").split("|")` 已处理，确认 md 表格格式标准 |
| HTML 注释进文档 | `<!-- -->` 没跳过 | 脚本检测 `<!--` 跳过多行到 `-->`，单行也要处理 |
| 中文乱码 | 编码问题 | 脚本 `open(md, encoding="utf-8")`，md 必须 UTF-8 |
| docx 里节标题编号后只剩单空格 | 脚本 162-170 行用 f-string 重建节标题文本（编号+空格+标题），把 md 源的编号后空格数压成 1 | 已改脚本为编号后双空格（人邮社规范）；规范若改回单空格需同步改脚本 f-string |
| 保存时报 `PermissionError`（目标 .docx 写不进） | 目标被 WPS/Word 占用（兄弟常开着 docx 看排版，尤其刚交付后） | **先生成到临时文件**（如 `_tmp_xxx.docx`）→ 尝试移动替换；被占用则保留临时文件并通知兄弟关闭后替换。别反复硬写目标 |
| 验证「不出现内容」假 FAIL | `'3.3.1' in full_text` 被 `13.3.1 服务器部署` 子串命中 | 逐行 `re.match(r'^3\.3\.[1-4]\s', t)` 行首锚定，见「重要注意事项」 |
